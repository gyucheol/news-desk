# 텔레그램 산업 흐름 선별 작업 (서브 에이전트 공통 지시)

목적: 사용자는 2026년 7월부터 지금(10월 4일)까지의 텔레그램 글로 "산업의 흐름"을 파악하려 합니다.
당신이 맡은 산업·기간의 글 목록을 읽고, 흐름을 보여 주는 요약 후보를 고르고 흐름을 정리합니다.
카드를 쓰거나 DB에 저장하지 않습니다. 결과 JSON 파일 하나만 씁니다.

## 입력 (모두 /home/user/news-desk/work 아래)
1. 글 목록: agent/<당신의 파일>.txt — 한 줄에 한 글. 탭 구분:
   ([산업]) 표시(N=한 번도 검토 안 함, R=예전에 다른 기준으로 훑고 넘김)  채널/id  MM-DD HH:MM(KST)  본문 앞 160자
   파일이 크면 Read의 offset/limit으로 나눠 읽으세요. 모든 줄을 빠짐없이 훑어야 합니다.
2. 산업 자료: brief/<산업>.txt — 산업 요약, 사이클 판정, 노드, 이미 반영된 흐름(flows), 이미 있는 카드 제목.
   반도체는 brief/macro.txt의 semis 노드를 보세요.
3. 미뤄 둔 후보: brief/deferred_newNote.txt (10월 2일 기록). 당신 산업에 해당하는 것은 결과에 포함하세요.
4. 예전 카드 제목(산업 구분 없음): brief/old_items.txt — 중복 확인이 필요할 때 Grep으로만 찾으세요(통째로 읽지 마세요).

## 판단 기준
- 고를 것: 산업의 수급·가격·재고·설비투자·정책·수요 변화처럼 흐름(사이클 국면)을 보여 주는 사실. 수치가 있으면 우선.
- 버릴 것: 종목 추천·주가 단평·잡담·광고·일정 공지·사진만 있는 글, 관심 산업과 무관한 글.
- 같은 사건을 다룬 여러 글(여러 채널 포함)은 후보 하나로 합치고 ids에 모두 적습니다.
- 이미 반영된 것(brief의 flows나 카드, old_items, 다른 후보)과 같은 사건이면 status를 dup으로 하고 무엇과 겹치는지 dupOf에 적습니다.
  새 사실(새 수치·후속 전개)이 있으면 status=follow(후속)로 둡니다.
- 글에 없는 내용을 지어내지 마세요. 본문이 160자에서 잘려 판단이 어려우면 note에 "본문 확인 필요"라고 적습니다.
- 추론은 추론이라고 밝힙니다(예: "추론: …").

## 출력
agent/out/<당신의 파일 이름에서 .txt를 뺀 것>.json 에 아래 형식으로 씁니다(한국어):
{
  "file": "...", "industries": [...], "period": "...",
  "counts": {"lines": 읽은 줄 수, "N": N 줄 수, "R": R 줄 수, "relevant": 흐름 관련으로 본 글 수},
  "flow": [ {"month": "2026-07", "industry": "...", "point": "그 달의 흐름 변화 한두 문장", "ids": ["채널/id", ...]} ],
  "candidates": [
    {"industry": "...", "node": "brief의 노드 id 또는 빈칸", "date": "MM-DD", "ids": ["채널/id", ...],
     "summary": "무슨 일인지 80자 이내", "why": "흐름에서 어떤 의미인지 60자 이내",
     "status": "new|follow|dup|deferred", "dupOf": "", "priority": "상|중|하", "note": ""}
  ]
}
- status=deferred는 deferred_newNote에 있던 후보(겹치는 새 글이 있으면 ids에 합침).
- priority 상: 흐름 판단을 바꾸거나 강화하는 핵심 사실, 중: 보강 사실, 하: 참고.
마지막으로 저에게는 파일 경로와 숫자(new/follow/deferred/dup 개수, 우선순위 상 개수)만 3줄 이내로 답하세요.
